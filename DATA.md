# Data

leastpriv ships two kinds of data. Neither comes from a real AWS account.

## 1. Action / resource catalog — `internal/catalog/data/catalog.json`

| | |
|---|---|
| What | 12 services (s3, dynamodb, lambda, sqs, sns, kms, secretsmanager, ssm, logs, iam, sts, ec2), 208 IAM actions with access level, resource types, ARN templates and the CloudTrail event names each action produces |
| Source | Hand-curated subset of the public [AWS Service Authorization Reference](https://docs.aws.amazon.com/service-authorization/latest/reference/reference.html) (action names, access levels, ARN formats) and the CloudTrail event names documented in each service's "Logging API calls with AWS CloudTrail" page |
| How built | `python3 scripts/gen_catalog.py > internal/catalog/data/catalog.json` from the compact table in that script; embedded into the binary with `go:embed` |
| Size | ≈32 KB |
| License | The catalog is factual interface data (API and permission names) restated in a new format; it is distributed under this repository's MIT license. No AWS documentation text is copied. |
| Caveats | A subset: actions and services not listed are ignored and reported as such. Access levels and event mappings are as documented when curated and can drift as AWS adds actions. |

## 2. Synthetic account — `testdata/acme/`

| | |
|---|---|
| What | `authz.json` (an IAM inventory in `aws iam get-account-authorization-details` format: 5 principals, managed/inline/group policies, one permissions boundary), `cloudtrail/<region>/<date>.json.gz` (9,561 CloudTrail records over 90 days, 2026-07-01 to 2026-09-28, in the S3-delivery log format), and `truth.json` (what each workload truly needs, how often, whether it is observable, and decoy requests it must never be allowed) |
| Source | Generated by this repository: `go run ./cmd/lp-synth --out testdata/acme` (seed 20260701, `internal/synth`). `make fixtures` regenerates byte-identical files; CI fails on any diff. |
| Size | ≈1.1 MB on disk |
| License | MIT (part of this repository) |
| Identifiers | Account `111122223333` is AWS's documentation example account; IP addresses are private (RFC 1918) or documentation ranges (RFC 5737); access-key IDs are placeholder strings. No real account, user or key appears. |
| Injected realism | Over-broad original policies (admin-in-two-regions CI role, `s3:*` on a bucket, a boundary that blocks IAM), noise records (access-denied attempts, AWS-service callers, events from a service outside the catalog), monthly/rare needs that may fall outside the training window, policy variables and MFA conditions. |

### Ground truth semantics

- `needs[]`: (action, resource pattern, frequency, observable) the workload requires. `observable: false` marks needs CloudTrail cannot show (e.g. data events not logged).
- `decoys[]`: sensitive (action, resource) requests the original policies may allow but the workload never needs; a good least-privilege policy denies them.
- `trainEnd`: the split point used by `lp-eval` (train 2026-07-01 to 2026-08-29, test 2026-08-30 to 2026-09-28).

Golden outputs in `testdata/golden/` are produced by the tool itself from this scenario (`make golden`) and reviewed by hand.
